# 董事会

本目录是一套独立的多 Agent 研究与决策系统。它使用“协调者分解与调度 → 成员并行独立研究 → 综合决策 Agent 选优”的扇出/汇聚架构，在控制无关上下文的同时容纳更多成员，最终输出当前证据与约束下的最优可执行解。它是正式一级功能目录，不是一个可独立触发的 Skill。

## 启动边界

- 只有用户明确说出“启动董事会决策”时，才读取并运行本目录中的决策内容。
- 普通咨询、“我该怎么办”、多角度分析、方案评审、复杂任务或仅提到董事会时，不读取本目录，也不主动建议启动。
- 用户明确要求维护董事会、添加人格 Skill 或整理成员时，可以读取本目录执行维护，但不得自动对当前问题召开董事会。
- 董事会过程和结论默认不写回；只有用户明确要求记录时，才写入 [决策记录](决策记录/README.md) 或其它合适事实目录。

## 运行路径

1. 协调者 Agent 建立共享决策包、研究关键事实、拆解任务并选择成员。
2. 入选成员通过独立任务信封并行研究；没有新增判断的成员输出 `PASS`。
3. 综合决策 Agent 去重、补充候选解、处理冲突、挑战领先方案并选择当前最优解。
4. 只有关键未知会改变最优解时，进行一次定向补充研究。
5. 未经明确要求不展开全员发言、不读取原包、不写入记录。

## 当前状态

- 系统 Agents：协调者 Agent、综合决策 Agent 已建立。
- 人格蒸馏 Skills：已启用 12 位只读适配成员。
- 运行模式：标准模式默认 6–10 名轻评审成员，2–4 名深评成员；支持扩展到 10–20 名轻评审成员。
- 上下文控制：共享决策包、独立任务信封、成员输入隔离、议事卡、`PASS` 弃权、一次定向补充轮。
- 最终交付：当前证据、约束与用户价值下的最优可执行解。
- 共同蒸馏来源：已归档女娲 Skill，不作为成员或普通 Skill 触发。
- 默认读取：关闭。
- 唯一启动指令：`启动董事会决策`。
